# declick 0.2.0 gap audit

Scope: nine finder lenses, every finding verified by two independent skeptics, three roadmap plans scored by a judge. Ground truth as of 2026-09-02, commit fbf8222. Duplicate reports are merged into one row each and the merge is noted, so the counts below are distinct defects, not reports.

## 1. Verdict

For one input class, an OpenAPI 3 JSON spec whose responses are flat arrays and whose bodies are strings, declick 0.2.0 keeps an agent in the shell end to end, and that is where the contract actually holds today. Outside it the agent leaves the shell on the first list call (`--limit` and `--fields` are no-ops on `{items:[...]}`, src/output.mjs:14-22), the first typed POST (integers and objects go out as strings, openapi.mjs:110-129), the first Swagger 2.0, YAML, Postman or MCP input, the first desktop task that needs a value read or a tree seen, and on the documented teardown command, which deletes the whole adapter and returns `ok:true` (bin/declick.mjs:188). The framing is right and 0.2.0 shipped it, but 115 distinct confirmed gaps (17 critical, 43 high), fifteen of which are silent-success paths, mean declick is roughly a third of the way to "agents never leave the shell": the contract is promised on every surface and kept on about one.
